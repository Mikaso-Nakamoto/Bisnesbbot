# Bisnesbbot

Система предварительных заявок на массаж. **Основной клиентский канал — VK**, Telegram — дополнительный. Оба канала используют одну SQLite-базу на ноутбуке и общее расписание. Уведомления тёте можно отправлять в VK и/или MAX; Telegram остаётся дополнительным вариантом. **ИИ не используется.** WhatsApp в проект не входит.

## Как проходит заявка

1. Клиент выбирает день и время.
2. Бот просит написать номер телефона.
3. Следующим сообщением показывает ровно три кнопки: **ВКонтакте**, **MAX**, **Телефонный звонок**.
4. Клиент указывает имя, проверяет сводку с датой, временем, номером и выбранным способом связи и подтверждает отправку **предварительной заявки**.
5. Заявка приходит тёте в настроенные админ-диалоги VK и/или MAX с теми же данными. Тётя связывается с клиентом и лично обсуждает детали. Только после этого отмечает «Договорились» или «Не договорились» в админ-интерфейсе VK/Telegram.

Заявка хранится **один раз**, независимо от канала создания. Пока тётя не отметила результат, слот удерживается для VK и Telegram. Если договориться не удалось, слот снова доступен. Ответ клиенту отправляется в исходный канал. Указанный телефон и предпочтительный способ связи видны тёте; бот сам не пишет на телефон, в VK или MAX.

MAX — отдельная интеграция, не VK API. Настройка MAX-бота нужна только для MAX-уведомлений; MAX-кнопок для принятия решения в этой версии нет — решение отмечается в подключённом интерфейсе VK/Telegram.

## Условное расписание

До получения реального графика используется **только демо-расписание**:

- часовой пояс: `Europe/Moscow`;
- понедельник–пятница: 10:00–18:00;
- суббота: 10:00–14:00;
- воскресенье: выходной;
- длительность: 60 минут;
- перерыв между слотами: 0 минут.

При `DEMO_MODE=true` бот предупреждает, что расписание условное. Любая заявка в любом режиме остаётся предварительной до личного согласования с тётей. Перед реальным использованием замени часовой пояс и расписание в `.env`; после этого можно установить `DEMO_MODE=false`.

Формат `WEEKLY_SCHEDULE_JSON`: ключи `0`–`6` означают понедельник–воскресенье; значение — список интервалов работы. Например, только понедельник и среда:

```dotenv
WEEKLY_SCHEDULE_JSON='{"0":[["10:00","16:00"]],"2":[["12:00","19:00"]]}'
```

Время задаётся в `TIMEZONE`. Длительность услуги задаётся в `SERVICE_DURATION_MINUTES`, перерыв — в `BUFFER_MINUTES`.

## Установка на Linux Mint 22 / Ubuntu 24.04

Нужен Python 3.11 или новее. На Mint 22 обычно уже установлен Python 3.12.

```bash
cd Bisnesbbot
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/pip install -e .
cp .env.example .env
chmod 600 .env
```

Открой `.env` в локальном редакторе. Не отправляй токены в чаты/ИИ и не добавляй `.env` в Git. Для запуска достаточно VK; Telegram можно подключить дополнительно.

## Настройка VK — основной канал

1. Создай или выбери сообщество VK. Включи сообщения сообщества.
2. В настройках сообщества открой раздел использования API: создай **ключ доступа сообщества** с правом на сообщения и включи **Bots Long Poll API**.
3. В настройках событий Long Poll включи как минимум `message_new` и `message_event` — первое нужно для входящих сообщений, второе для кнопок.
4. Узнай числовой ID сообщества и заполни `.env`:

   ```dotenv
   VK_GROUP_TOKEN=ключ_сообщества
   VK_GROUP_ID=числовой_ID
   VK_ADMIN_USER_IDS=
   ```

   Используй именно ключ сообщества, не личный токен пользователя.
5. Открой диалог с сообществом с аккаунта тёти и отправь `/myid`. Добавь показанный ID в `VK_ADMIN_USER_IDS`, затем перезапусти программу:

   ```dotenv
   VK_ADMIN_USER_IDS=123456789
   ```

   Тётя должна сама первой открыть диалог/написать сообществу — после этого бот сможет присылать ей заявки в VK.

VK-бот использует Long Poll, поэтому для него не нужен публичный домен или открытый входящий порт. Ноутбук должен быть включён и иметь доступ к API VK.

## Уведомления тёте в MAX (по желанию)

MAX подключается **отдельным MAX-ботом и отдельным токеном** — токен VK для этого не подходит. Создай MAX-бота через доступный для профиля тёти официальный маршрут MAX для бизнеса, затем укажи токен в локальном `.env`:

```dotenv
MAX_BOT_TOKEN=токен_MAX_бота
MAX_ADMIN_USER_IDS=
```

Тётя должна первой открыть диалог с MAX-ботом и отправить ему любое сообщение. Чтобы получить её ID, выполни в папке проекта:

```bash
.venv/bin/python scripts/get_max_admin_id.py
```

Добавь показанный ID в `MAX_ADMIN_USER_IDS` и перезапусти программу. Несколько ID можно перечислить через запятую. Скрипт использует `GET /updates` только для разового определения ID; официальная документация MAX рекомендует Webhook для рабочего получения событий. Если у MAX-бота уже настроен Webhook, возьми ID из события `bot_started` или `message_created`. Токен хранится только в `.env`; не присылай его в чаты.

MAX получает копии заявок. Для отметки результата тёте нужно открыть уведомление в подключённом VK или Telegram: управление заявками через MAX в этой версии не реализовано.

## Дополнительный Telegram-канал

Если хочешь получать копии заявок и принимать решения в Telegram, создай Telegram-бота и добавь в `.env`:

```dotenv
BOT_TOKEN=токен_telegram_бота
ADMIN_TELEGRAM_IDS=123456789
```

Узнать Telegram ID можно командой `/myid` в личном чате бота. Тётя должна первой отправить ему `/start`. Если Telegram пока не подключаешь, оставь `BOT_TOKEN` и `ADMIN_TELEGRAM_IDS` пустыми.

Клиент сам вводит номер телефона и выбирает один из трёх способов связи: VK, MAX или телефонный звонок. Telegram — только дополнительный канал для самой заявки и копий уведомлений; выбирать его как способ связи с клиентом нельзя. Тётя увидит номер и выбранный способ в уведомлениях VK/MAX (и в Telegram, если он отдельно настроен).

## Запуск

```bash
.venv/bin/bisnesbbot
```

Проверь сетевой доступ процесса Python к VK API и, если настроен, Telegram API. VK-адаптер учитывает стандартные переменные окружения HTTP/HTTPS proxy; маршрутизацию Telegram через Xray проверь отдельно.

## База, статусы и резервные копии

Файл общей базы по умолчанию: `data/bisnesbbot.sqlite3`. Он создаётся автоматически. При запуске существующая SQLite-база автоматически дополняется полями для способа связи и контакта; старые заявки сохраняются, но введённого контакта у них не будет.

В Git не попадут ни база, ни её WAL-файлы. Настрой резервное копирование на **другое устройство или диск**: копия на том же ноутбуке не защищает от отказа диска. Скрипт использует SQLite backup API, поэтому безопасно копирует работающую базу в режиме WAL:

```bash
.venv/bin/python scripts/backup_db.py data/bisnesbbot.sqlite3 /путь/на/другой/диск/bisnesbbot.sqlite3
```

Статусы заявки:

- `pending` — предварительная заявка, ждёт личного согласования и удерживает слот;
- `confirmed` — тётя отметила, что после личного общения вы договорились;
- `declined` — договориться не удалось, слот снова доступен.

Контакт, указанный клиентом, виден в уведомлениях и списке ожидающих заявок и хранится в локальной SQLite-базе. Если уведомление в одном канале не доставлено, сама заявка остаётся в базе; её можно найти в другом подключённом админ-канале.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check src tests scripts
```

Live-проверка VK требует ключ сообщества, ID сообщества, включённые события Long Poll и личный диалог тёти с сообществом. Для MAX-уведомлений нужны отдельный MAX Bot API token и ID пользователя тёти; эти значения заполняются только в локальном `.env`. Пока реальные данные не введены на ноутбуке, проверяется только логика приложения и SQLite.
