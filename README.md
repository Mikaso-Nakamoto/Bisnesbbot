# Bisnesbbot

Система записи на массаж. Первая версия — Telegram-бот с общей SQLite-базой на ноутбуке. **ИИ не используется.**

## Что уже умеет MVP

- показывает даты и свободные слоты по недельному расписанию;
- принимает имя клиента и сохраняет заявку в SQLite со статусом `pending`;
- временно блокирует слот, пока тётя не примет решение;
- отправляет администратору заявку с кнопками **«Подтвердить»** и **«Отклонить»**;
- после подтверждения сообщает клиенту о записи, после отказа освобождает слот;
- не позволяет двум заявкам занять пересекающееся время;
- позволяет администратору посмотреть ожидающие заявки командой `/pending`.

Поддержка VK и MAX пока не подключена: модель записи и поля источника заявки уже подготовлены так, чтобы добавить эти интерфейсы к той же базе. WhatsApp в проект не входит.

## Условное расписание

До получения реального графика используется **только демо-расписание**:

- часовой пояс: `Europe/Moscow`;
- понедельник–пятница: 10:00–18:00;
- суббота: 10:00–14:00;
- воскресенье: выходной;
- длительность: 60 минут;
- перерыв между слотами: 0 минут.

При `DEMO_MODE=true` бот предупреждает, что расписание условное и запись не подтверждена. Перед реальным использованием нужно заменить часовой пояс и расписание тёти в `.env`, затем установить `DEMO_MODE=false`.

Формат `WEEKLY_SCHEDULE_JSON`: ключи `0`–`6` означают понедельник–воскресенье; значение — список интервалов работы. Например, только понедельник и среда:

```dotenv
WEEKLY_SCHEDULE_JSON='{"0":[["10:00","16:00"]],"2":[["12:00","19:00"]]}'
```

Время задаётся в `TIMEZONE`. Для каждой услуги можно настроить `SERVICE_DURATION_MINUTES` и `BUFFER_MINUTES`.

## Установка на Linux Mint 22 / Ubuntu 24.04

Нужен Python 3.11 или новее. На Mint 22 обычно уже установлен Python 3.12.

```bash
cd Bisnesbbot
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/pip install -e .
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и задайте токен Telegram-бота в `BOT_TOKEN`. Сам файл `.env` исключён из Git. Не отправляйте токен в чат и не добавляйте его в репозиторий.

## Настройка администратора

1. Запустите бота без `ADMIN_TELEGRAM_IDS` и откройте с телефона тёти личный чат с ботом.
2. Тётя отправляет `/start`, затем `/myid`.
3. Скопируйте показанный числовой ID в `.env`, например:

   ```dotenv
   ADMIN_TELEGRAM_IDS=123456789
   ```

   Несколько администраторов можно перечислить через запятую.
4. Перезапустите бота.

Администратору нужно первым открыть бота и нажать `/start`, иначе Telegram не позволит боту написать ему первым. После запуска заявки также доступны по `/pending`.

Если администратор не настроен, заявки всё равно сохраняются в базе со статусом `pending`, но подтвердить их некому; при запуске будет предупреждение.

## Запуск

```bash
.venv/bin/bisnesbbot
```

Бот работает через Telegram long polling: для первого запуска не нужны домен, публичный IP или открытый входящий порт. Ноутбук должен быть включён и не должен уходить в сон. Если Xray настроен только для браузера, отдельно проверьте, что процесс Python тоже может подключиться к Telegram API.

## База и резервные копии

Файл базы по умолчанию: `data/bisnesbbot.sqlite3`. Он создаётся автоматически. В Git не попадут ни база, ни её WAL-файлы. Настройте резервное копирование на **другое устройство или диск**: копия на том же ноутбуке не защищает от отказа диска. Скрипт использует SQLite backup API, поэтому безопасно копирует работающую базу в режиме WAL:

```bash
.venv/bin/python scripts/backup_db.py data/bisnesbbot.sqlite3 /путь/на/другой/диск/bisnesbbot.sqlite3
```

Заявка сохраняется в базе до отправки уведомления. Решение тёти меняет её статус:

- `pending` — ожидает ответа и удерживает слот;
- `confirmed` — подтверждена и удерживает слот;
- `declined` — отклонена, слот снова доступен.
